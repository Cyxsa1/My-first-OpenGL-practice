   📂 第一步：准备文件（物理层面）
假设你的项目文件夹在 D:\Projects\My first Project

1.头文件
 把你下载的 glfw3.h、glad.h 文件（通常在 glfw-3.x.x.bin.WIN64\include\GLFW 里），放在项目目录下的 include 文件夹里。
 结构示例： D:\Code\My first Project\include\glad.h
            D:\Code\My first Project\include\GLFW\glfw3.h

2.库文件
 把 glfw3.lib（以及其他你需要的 .lib 文件），直接放在 项目根目录（就是和 .sln 文件在一起的地方），或者放在一个专门的 lib 文件夹里。
 结构示例： D:\Code\My first Project\glfw3.lib

   ⚙️ 第二步：配置属性（VS 层面）
 在 Visual Studio 右侧“解决方案资源管理器”中，右键点击项目名称 -> 属性。
  //重要提示： 每次配置前，请务必检查顶部的 “配置” 选为 “所有配置”
   （否则你在 Debug 配好了，切到 Release 又报错）
    “平台” 选为 “x64”（除非你用的是老旧的 32 位库）。

1. 配置包含目录（解决 E1696 无法打开源文件）
这一步是告诉编译器：#include <...> 的时候去哪里找文件。

 路径： C/C++ -> 常规 -> 附加包含目录
 操作： 点击编辑，添加你的头文件路径。

2.填写内容：
$(ProjectDir)include

  //解释： $(ProjectDir) 是一个宏，代表项目根目录。这样写比写死 D:\... 更好，方便以后把项目发给别人。

 <配置库目录（可选，如果库文件在项目根目录则不需要）

 如果你的 .lib 文件直接扔在项目根目录（和 .sln 在一起），这一步其实可以跳过，因为 VS 默认会搜索那里。但如果你建了一个 lib 文件夹，就需要这一步。
 路径： 链接器 -> 常规 -> 附加库目录
 操作： 添加你的 .lib 文件所在的文件夹路径。

填写内容：
$(ProjectDir)

或者如果你建了 lib 文件夹：
$(ProjectDir)lib>

3. 配置附加依赖项（解决 LNK2019 无法解析的外部符号）

 这一步是告诉链接器：打包程序时，需要把哪些 .lib 文件链进去。=编译时需要链接哪些 .lib 文件
 路径： 链接器 -> 输入 -> 附加依赖项
 操作： 点击编辑，一行一个地输入库文件名。

填写内容：
glfw3.lib
opengl32.lib

//注意： 只需要写文件名，不需要写路径。

//解释：
 glfw3.lib：是你刚才复制进去的 GLFW 库。
 opengl32.lib：是 Windows 系统自带的 OpenGL 库，必须加上。

📝 第三步：编写代码（代码层面）

配置完环境后，你的代码文件开头应该是这样的：
// 1. 必须先包含 glad，因为它包含了特定于平台的 OpenGL 头文件
#include <glad/glad.h>//或#include <glad.h>
// 2. 再包含 GLFW
#include <GLFW/glfw3.h>

int main() {
    // 你的 OpenGL 代码...
    return 0;
}
//原因：GLAD 包含了 OpenGL 的头文件，它需要在 GLFW 之前加载，否则会发生冲突。

🚀第四步：运行与调试

  检查代码：确保没有红色波浪线。
 生成解决方案：点击菜单栏 生成 -> 生成解决方案（看输出窗口是否显示“成功 1 个”）。
 运行：点击绿色的 本地 Windows 调试器。

  如果运行报错“找不到 glfw3.dll”：

这说明你把 glfw3.dll（在 glfw-3.x.x.bin.WIN64 里）漏掉了。
//解决：把 glfw3.dll 复制到 My first Project.exe 同级目录下（通常在 Debug 文件夹里），或者直接放在项目根目录。

💡 总结
//如果还是报错，请对照检查：
 属性页顶部的“配置”是否选了所有配置？
 属性页顶部的“平台”是否选了x64？
 附加包含目录 是否指向了 include 文件夹？
 附加依赖项 是否加了 glfw3.lib 和 opengl32.lib？
 代码里是否先 #include <glad.h>？


只要记住这三个关键点，任何 C++ 第三方库（如 OpenCV, SDL, Qt 等）的配置逻辑都是一样的：
文件放好（Include 和 Lib）。
包含目录（告诉编译器头文件在哪）。
附加依赖项（告诉链接器库文件是谁）。
没问题！既然你已经成功运行了，那我们把刚才的操作复盘一下，整理成一套标准、详细且可复用的步骤。

配置环境的核心逻辑其实就三步：
物理层面：把下载的文件放到项目里。
VS层面：告诉编译器头文件在哪（解决 #include 报错）。
链接层面：告诉链接器库文件在哪（解决 LNK2019 报错）。
你可以把下面这份指南保存下来，以后建任何 C++ 项目（不管是用 OpenCV、Qt 还是其他库），流程都是通用的。
